# ADR 0019: Stable 1.0.0 release

Status: accepted
Date: 2026-08-30

Supersedes the prerelease requirement in [ADR 0010](0010-publish-prerelease-packages.md) for
releases from `v1.0.0` forward. ADR 0010 is not retracted; its reasoning still applies to a
pre-adopter library, and the rule is restated below as a still-future condition for any future
0.x branch.

## Context

ADR 0010 (2026-08-05) sets the prerelease policy:

> The suffix comes off when there are adopters whose code an API change would break. Until then
> there is nothing to stabilise for, and a 1.0 declared without users is a promise to nobody.

The library now has such an adopter. [The August 2026 gap analysis][gap] is a
concrete integration plan from a downstream product (internally "private-project") that would consume
`LakeWright.Embedding` and `LakeWright.Databricks`. Each gap the analysis names
corresponds to a public surface the adopter would have to call, and each closed gap
narrows the surface the adopter is depending on. Six of the eight items landed in
the same window:

| Gap | Resolution | PR |
| --- | --- | --- |
| §1.1 net8.0 target | Multi-target `LakeWright.Embedding` and `LakeWright.Core` for `net8.0` | #92 |
| §2.2 `ScopeVersion` | `TenantContext.ScopeVersion` plumbed through the broker | #93 |
| §3.1 token cache | `MemoryWorkspaceTokenCache` (ADR 0018) | #94 |
| §3.2 dual SP | Embed and ops principals split (ADR 0016) | #95 |
| §3.4 publish gate | Tenant-scope `external_value` enforced (ADR 0017) | #96 |
| §3.5 chunked export | `ITenantScopedExport.StreamAsync` over `EXTERNAL_LINKS` | #97 |

[gap]: ../../Downloads/LakeWright-NET-gap-analysis-2026-08-30.md

The condition ADR 0010 names is met. The remaining gap items — §1.2 itself and §2.1
schema-per-tenant — are not blockers: §1.2 is what this ADR closes, and §2.1 is the
library's documented posture (one catalog per tenant, never shared).

## Decision

Cut a `v1.0.0` release that publishes stable packages to nuget.org. The prerelease guard in
`release.yml` is removed; a version that lacks a hyphen is no longer a workflow failure.

The compat promise is the one the rest of the project has been holding: **breaking changes
between 1.0.0 and 2.0.0 ship behind a SemVer minor bump and a CHANGELOG migration note.** The
`docs/compatibility.md` matrix, with its Verified / Documented / Unverified split, is the
single source of which surface has been shown to work against a real workspace. A `Documented`
row is honest about the gap and a `Unverified` row is honest about the unmeasured risk —
neither is a claim of correctness, and a stable version number does not make them one. The
honesty is the promise.

What does and does not change in 1.0.0:

- The public type and member surface listed in `## [1.0.0]` of `CHANGELOG.md` is the
  committed shape. Subsequent surface changes go through `2.0` or a new major, with the
  CHANGELOG recording the migration.
- `Directory.Build.props`'s `VersionPrefix` becomes `1.0.0`. A local `dotnet pack` that
  bypasses the tag-derived override would still name the version it claims.
- The release workflow continues to derive the package version from the tag, continue to
  refuse a lightweight or unsigned tag, and continue to attest provenance and push to
  nuget.org under the same OIDC trusted-publishing policy.
- `docs/compatibility.md` keeps its row-by-row format. A stable version does not promote a
  `Documented` row to `Verified`; a future verification is the only thing that does that.

What this ADR does not claim:

- That 1.0.0 is feature-complete. The `ROADMAP.md` open work and the `docs/compatibility.md`
  `Unverified` rows describe what is still owed. Cutting 1.0.0 is the start of stabilizing
  what is there, not the end of building it.
- That the gap-analysis reader's other products are blocked on anything else in this repo.
  The "Bottom line" in the analysis is that closing §1.1, §1.2 and §2.2 is what the
  integration needs; those are exactly what this release delivers.

## Consequences

**A package id is permanent.** nuget.org unlists but never deletes. `LakeWright.*` and the
package names under it are now reserved, which is the side effect ADR 0010 already accepted for
the prerelease packages. The stable release extends that permanence to the version strings
themselves, which is why breaking a 1.x contract is a 2.0 event rather than a `1.0.x` one.

**The compat promise is enforced by the same practices that built the surfaces, not by a
gate.** A test that catches the regression is the only thing that proves a contract, and
the existing test suite is what is doing the enforcement. The compat matrix is the human
read of what the test suite says, and the matrix itself does not have an enforcement
mechanism — it has a workflow check that documents claims the repository contradicts
(`scripts/check-doc-claims.sh`), which is the closest the project comes to a lint over
its own claims.

**Download counts still measure discovery.** The 0.x download counts were a signal, and
the 1.x counts are the same signal. ADR 0010's caveat applies unchanged.

**The `0.x` line ends with `0.1.2-preview.1`.** A `v0.1.3-preview.x` is still publishable
under the old guard if a fix needs to ship before 1.0.0 is cut. The decision here is to
remove the guard, not to forbid prereleases: the workflow still names a tag with a hyphen
as a SemVer prerelease in the GitHub release, and `nuget push --prerelease` is still the
right thing for an unpublished interim fix.

**The OIDC trusted-publishing policy is the same policy.** The new tag does not change
which owner / repository / workflow file nuget.org's policy names, and the existing
`NUGET_USER` repository variable is what gates the push. A lapsed policy still warns
rather than fails, and the warning is the same one ADR 0010 documents.

## Tag and push (the user's step, not the repository's)

`v1.0.0` is signed (`git tag -s v1.0.0 -m '...'`) and pushed. The release workflow handles
the rest: deriving the version, refusing an unsigned or lightweight tag, restoring, building,
testing, packing, attesting provenance, generating the SBOM, creating the GitHub release, and
exchanging the OIDC token for the nuget.org key.

Cutting the tag is the only step that needs the maintainer's GPG key and push permission.
Everything else in the release has been run in the 0.x line; this is the same workflow with
the prerelease guard removed.
