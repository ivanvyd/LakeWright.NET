# 2.1.0 release evidence

Stable release completed on 2026-09-12.

The signed release-candidate and stable tags resolve to commit
`25d5f4a68cf3a9a2eb86e78177b1a3ebc8f74242`. The
[release-candidate workflow](https://github.com/ivanvyd/LakeWright.NET/actions/runs/34699044625)
published [v2.1.0-rc.1](https://github.com/ivanvyd/LakeWright.NET/releases/tag/v2.1.0-rc.1), and the
[stable release workflow](https://github.com/ivanvyd/LakeWright.NET/actions/runs/34699657778)
then published [v2.1.0](https://github.com/ivanvyd/LakeWright.NET/releases/tag/v2.1.0). Each workflow
completed its signed-tag, confidentiality, build, test, package-order, SBOM, provenance, and public
NuGet-index gates before creating its GitHub release.

The stable release published all thirteen package surfaces: AI, AspNetCore, Caching.Distributed,
Caching.Redis, Conversations, Core, Databricks, Databricks.RawData, Embedding, Embedding.Ops,
HealthChecks, Multitenancy, and Tooling. An independent public-index check found both `2.1.0-rc.1`
and `2.1.0` for every package, with `2.1.0` as the latest stable version. The stable GitHub release
contains all thirteen primary packages and the CycloneDX SBOM.

After publication, a clean net8 consumer restored stable `2.1.0` packages from nuget.org into a
fresh package cache, built, ran, and printed `OK`. The exact public `LakeWright.Tooling` 2.1.0
package installed into a fresh tool directory and inspected the safe dashboard fixture with
`Passed: true`. The downloaded Core package's SHA-256 matched the digest recorded on the GitHub
release.

GitHub's attestation API exposes SLSA provenance for the stable packages with the release workflow
as builder and the merged commit as source. A subsequent local `gh attestation verify` retry could
not complete because the Sigstore public TUF verifier failed while loading its trust material; the
same command had completed for the release candidate earlier in the verification session. This is
recorded as a verifier limitation rather than as an additional successful cryptographic check.

The merged-source CI completed confidentiality preflight and history scans, Release build and
format checks, vulnerability scanning, 465 non-live tests, 401 tenant-isolation tests, documentation
and bundle checks, package consumer validation, CodeQL, dependency review, load-harness validation,
and Azure template validation. The Azure deployment job was deliberately skipped; the repository's
reference template is not a production deployment claim.

This evidence records package publication and automated validation. It does not claim a live
Databricks workspace execution, an Azure production deployment, or a named downstream adopter.
