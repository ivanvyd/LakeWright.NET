# 1.1.1 release evidence

Patch-release preparation on 2026-09-01. Publication evidence will be added after the immutable
signed-tag workflow completes.

## Scope

The v1.1.0 post-ship panel found that the billing report window was bounded only by the HTTP
endpoint. Direct consumers of the public attribution service or billing reader could therefore
request a multi-year account-wide scan. It also found no process-level protection against many
concurrent billing statements.

The patch moves the 31-day and one-day-future limits into a shared Core validator used by both the
tenant attribution service and Databricks reader. The HTTP layer retains the same early 400
responses. The billing reader is now a stateless singleton with a configurable process-wide bound
on concurrent and outstanding statement lifecycles. Saturation fails closed with transient code
`BILLING_BUSY`, mapped to HTTP 503. Billing submissions also use server-side timeout cancellation;
when a create response is lost, the local admission slot is held through that deadline before the
safe transient result `STATEMENT_CREATE_UNCERTAIN` is returned.
