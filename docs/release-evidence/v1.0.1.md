# 1.0.1 release evidence

Run 2026-09-01. This page was added after publication because post-ship review found that the
compatibility matrix recorded the Compose lifecycle but not the HTTP requests or package-consumer
commands. The signed `v1.0.1` tag and its immutable release were not changed.

## Environment repair

Docker Desktop 4.85.0 could not create its `dockerInference` AF_UNIX endpoint. Updating to the
signed 4.88.1 installer reproduced the failure, so the version was not the root cause. Windows
AF_UNIX bind/delete worked in an isolated socket probe. Docker started after its transient
`run` and `docker-secrets-engine` directories were moved aside together and recreated.

The repair did not use factory reset and did not delete images, volumes or settings. The old
runtime directories remain under Local AppData as `run.stale-20260901-1312`,
`run.stale-20260901-1316` and `docker-secrets-engine.stale-20260901-1314`.

The repository lock files require the .NET 10.0.11 framework assets. The machine was upgraded to
SDK 10.0.400, which carries those assets, before locked restore was rerun. The SDK was immediately
usable, but Windows still reported 32 pending file-renames. Reboot the machine when practical to
finish the installer cleanup.

```text
docker desktop status
docker version
docker run --rm hello-world
dotnet --info
```

Result: Docker Desktop reported running; engine 29.7.2 served Linux/amd64 containers; the freshly
pulled container exited successfully; .NET selected SDK 10.0.400.

## Signalboard

The sample ran under a unique Compose project so it could not collide with another stack:

```text
docker compose -p lakewright-v101-local -f samples/Signalboard/compose.yaml up -d --build
```

These PowerShell requests exercised readiness, the public API document, idempotency, tenant
isolation and role authorization:

```powershell
$base = 'http://localhost:8080'
$acme = '0198f000-0000-7000-8000-00000000ac11'
$headers = @{
    'X-Demo-User' = 'demo|alice'
    'Idempotency-Key' = 'codex-v101-local'
}

$health = Invoke-WebRequest -Uri "$base/health"
$openapi = Invoke-WebRequest -Uri "$base/openapi/v1.json"
$first = Invoke-WebRequest -Method Post `
    -Uri "$base/organizations/$acme/operations" `
    -Headers $headers -ContentType 'application/json' -Body '{"kind":"analysis"}'
$second = Invoke-WebRequest -Method Post `
    -Uri "$base/organizations/$acme/operations" `
    -Headers $headers -ContentType 'application/json' -Body '{"kind":"analysis"}'
$firstBody = $first.Content | ConvertFrom-Json
$secondBody = $second.Content | ConvertFrom-Json
$crossTenant = Invoke-WebRequest -Uri "$base/organizations/$acme/operations/$($firstBody.id)" `
    -Headers @{ 'X-Demo-User' = 'demo|bob' } -SkipHttpErrorCheck
$viewer = Invoke-WebRequest -Method Post -Uri "$base/organizations/$acme/operations" `
    -Headers @{
        'X-Demo-User' = 'demo|vera'
        'Idempotency-Key' = 'codex-v101-viewer'
    } `
    -ContentType 'application/json' -Body '{"kind":"analysis"}' -SkipHttpErrorCheck

[pscustomobject]@{
    Health = $health.StatusCode
    OpenApi = $openapi.StatusCode
    FirstPost = $first.StatusCode
    ReplayPost = $second.StatusCode
    SameOperation = ($firstBody.id -eq $secondBody.id)
    CrossTenantRead = $crossTenant.StatusCode
    ViewerPost = $viewer.StatusCode
}
```

Result: health and OpenAPI returned 200; both creates returned 202 with the same operation ID;
the cross-tenant read returned 404; the Viewer create returned 403.

```text
docker compose -p lakewright-v101-local -f samples/Signalboard/compose.yaml down -v
```

After cleanup, no matching container, network or volume remained.

const string first = "SELECT * FROM a WHERE __aibi_external_value = :tenant_id";

var single = DashboardPublishGate.Inspect(first);

if (!single.Passed || single.Hits.Single().DatasetIndex != 0
    || !all.Passed || all.Hits.Select(hit => hit.DatasetIndex).ToArray() is not [0, 1])

## Merge and publication

Pull request [#102](https://github.com/ivanvyd/LakeWright.NET/pull/102) passed build, tests, tenant
isolation, documentation, bundle validation, load harness, dependency review and CodeQL before it
was squash-merged as `ead8ae6`.

```text
git tag -s v1.0.1 -m "v1.0.1" ead8ae6ebf50edf7e71b991ef715820e9b3000ea
git push origin v1.0.1
gh run watch 33516900884 --exit-status
```

GitHub verified the tag's SSH signature. The Release workflow accepted the signed tag, restored,
built, tested, packed, generated a 47-component CycloneDX SBOM, attested provenance, created the
GitHub Release and exchanged GitHub OIDC for a short-lived NuGet key. NuGet returned HTTP 201 for
all seven packages and all seven symbol packages.

Each published package was downloaded from the release and verified with the same constraints:

```text
gh attestation verify <package> \
  --repo ivanvyd/LakeWright.NET \
  --signer-workflow ivanvyd/LakeWright.NET/.github/workflows/release.yml \
  --source-ref refs/tags/v1.0.1 \
  --source-digest ead8ae6ebf50edf7e71b991ef715820e9b3000ea
```

All seven attestations passed and every downloaded SHA-256 digest matched its GitHub Release asset.
After all seven versions appeared in the public NuGet V3 index, a second temporary consumer used a
new isolated package cache and a NuGet configuration containing only nuget.org:

```powershell
$env:NUGET_PACKAGES = '<empty-temporary-package-cache>'
dotnet restore Consumer.csproj --configfile NuGet.Config --force --no-http-cache
dotnet run --project Consumer.csproj --no-restore -c Release
```

Result: the package downloaded into the empty cache and the same program printed
`Inspect=0, InspectAll=0,1`.
